Read the brief and project rules, then verify the pinned manifest at session start. Research real reference work and techniques that address the actual audience and task. Record source, date, relevant detail, and how it informs or challenges the project's visual idea. Do not copy protected work or turn a reference into a default template. Before writing under `/workspace/design-output/<project>/`, run `"$FANNAN_RELEASE/tools/readonly-precheck.sh" "/workspace/design-output/<project>/" "<project>"`; see [security and install](../../references/security-and-install.md). Remain read-only on external sites and the repo. Never post or buy access without Fadel's yes.

## Gotchas

- A reference helps the critic judge craft; it does not approve content facts or override the brief.
