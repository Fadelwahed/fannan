# Labelled example: supplied example project dry-run

This is an example-only desk check against the supplied pack's example project settings and project rules files (`input/fannan-review-pack/example-project-*`; their names and hashes are in the pack manifest). It is not a new design, an approval or a claim that the source facts are confirmed. No example facts belong in generic skills or memory.

| Workflow question | Observed input | Correct outcome |
|---|---|---|
| Can Step 1 resolve authority? | Settings names vendors and a code host, but does not provide the complete four-role mapping and authoritative implementation-stack field required by this contract | BLOCK Step 9; request the project records owner to complete settings. Do not extract names from generic bot memory |
| Are rules authoritative? | The rules file explicitly says DRAFT and not yet the source of truth; it refers to newer approvals and files not supplied | Use as an example constraint inventory; obtain the approved rule revision before displaying final copy |
| Can copy be invented to improve the hero? | Rules quote approved home lines and a main CTA, but the actual referenced brief/writer deck and fact register are absent | Preserve quoted wording as example source data only. Flag any generic-headline conflict to writer/approver. Do not invent a replacement or certify a claim |
| Are proof claims safe to display? | The example has restrictions on locations, partner names, certifications and client consent, and refers to a checked fact register elsewhere | Apply those example restrictions in the dry-run; final factual content stays blocked until the actual confirmed register and required permissions are provided |
| Can styling begin now? | The complete approved desktop wireframe set and current authoritative brief are not in the pack | No. Do not infer Step 5 approval from the presence of a final-plan document |
| Can multilingual layouts be finalized? | The example distinguishes present launch language from a later language/direction | Preserve that phase distinction in project settings; test only authorized design scope and record future work deferred |
| Can the engineer start a build? | No approved frame set, private design link, complete copy deck, real acceptance bundle or final approval record is supplied | No Step 9. An honest blocker is the correct result of this example check |

The workflow therefore succeeds at detecting incomplete authority, source and handoff inputs. It has **not** demonstrated that a finished design for the example project passes the quality or accessibility gate. The source example's pending legal, privacy, client-consent and sitemap decisions are not resolved by this rewrite.
