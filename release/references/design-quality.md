# Integrated design and copy acceptance

Load at section planning, the Step 4/5 grayscale review and the Step 8 pre-handoff check. This is the rulebook for `tools/pre-handoff-check.mjs`, not an optional separate review. The machine thresholds are in `runtime/quality-checks.json`; semantic verdicts and evidence live in the same `handoff.json` used by the checker. A missing required manual check fails acceptance. Automated detectors identify measurable patterns; a human/independent critic checks meaning and visual exceptions. Neither is an authorship detector. Impeccable findings are advisory: its `pass` means the pinned detector ran and produced parseable output, not that it found no design problems. The gate separately requires the scoped critic/manual PASS records for generic heroes, rounded-card grids, dashboard tropes, decoration and other semantic criteria; absent or failed records block handoff.

## Measurement contract

The reference viewport is 1440 × 900 CSS pixels at device scale one, with a full-page screenshot as well. Visit every declared screen and applicable state. Wait for local fonts and assets; log failed or blocked loads. Keep external requests, service workers and WebSockets blocked during the local check. Capture file hashes and the version under test. A reference PNG is 1440 pixels wide and named `screen--state--locale--vNN.png`; its hash identifies the version. A screenshot from another revision cannot support a PASS. The checker also renders every declared `settings.desktopWidths` width and 320 CSS px (the 400% reflow equivalent of a 1280 px desktop) and fails horizontal overflow, text that actually overflows a hidden or clipped box (ellipsis styling alone is not a failure; `body` is screened too, so `overflow-x: hidden` or `clip` on `html` and `body` cannot hide a wide layout), text or media pushed past the left edge (except inside a horizontal scroller, visually hidden sr-only content of at most 1×1 px or `clip: rect(0 0 0 0)` / `clip-path: inset(50%)`, and a focusable off-screen skip link that appears on focus) and a language/direction mismatch; this is a screen, not mobile approval, and manual zoom and text-spacing evidence stays required.

Mark visible text wrappers with `data-copy-slot="ID"` and match every displayed string to the approved locale variant in the copy deck, including interface and error labels. Unlisted or mismatched text blocks final handoff. Declare semantic section, component, copy-slot and media IDs in the reference DOM and match them to the handoff inventory. The critic inspects the full screenshot and semantic outline so unmarked containers cannot evade a count. CSS/computed-style counts are recorded as measurements. Layout intent, claims, tasteful restraint and the purpose of an image remain reviewed judgments with an artifact, reviewer, explanation and brief line references. A guessed PASS flag is not evidence.

Where the browser test uses a proxy, label it as a proxy in `evidence.json`. In particular, DOM element rectangles do not measure the actual colored pixels of text, images, gradients or overlapping regions. For accent coverage, the documented acceptance measure is visible accent area divided by total rendered area, separately for the full page and each reviewed viewport. The reviewer supplies an annotated color mask or measured screenshot regions for image/canvas/SVG content and any disputed DOM estimate. Use union area, not summed overlapping boxes. Borderline or unmeasurable coverage remains FAIL pending evidence; do not round 10.1% down to 10%. The automated accent screen fails closed: if a declared accent token (`--accent`, `--colors-accent`, `--colors-primary`) is not a valid colour, or no accent token is declared, the ratios are null and the handoff check fails; it is never treated as zero accent.

The automated probes and axe run in a separate browser world (`tools/probe-world.mjs`, a CDP isolated world; Chromium only): they see the page's DOM and CSS but not its JavaScript globals, so a page script cannot patch `getComputedStyle`, `querySelectorAll` or `axe` to hide a failure. `tools/integrity.mjs` cross-checks the positional page: the same probes in the page's own world (a difference is a tampering sign), the page world's probe functions (they must still be native), and a JavaScript-off pass. More glass or a failing 320 px screen with JavaScript off fails as `integrity mismatch` unless the handoff's `jsOffDifferences` records the expected difference with a reason. Text contrast is cross-checked with JavaScript off too: CSS opacity and `filter: opacity()` on the text and its ancestors are composited; any other filter, a blend mode, a backdrop filter or a mask on the chain cannot be resolved, so that text is counted in `contrastEffects` and the cross-check is INCOMPLETE, never a silent pass (the glass hard fail is unchanged). Native control text (input and textarea values or placeholders, button-type input labels, a select's chosen option) is contrast-checked, and the content comparison records each control, link, image and labelled element with its accessible name and displayed value, so a label, value or `aria-label` that only script supplies makes the JavaScript-off content differ.

Unresolved compositing on displayed text in either rendering blocks handoff as INCOMPLETE. Token contrast proofs and `jsOffDifferences` cannot waive it. Retaining the effect requires a reviewed measurement implementation that resolves its actual composition for every applicable rendering. Backdrop-filter remains a hard FAIL.

Rendered-visibility backstop: the CSS contrast computation is the first pass; what the browser actually painted is the backstop, in both renderings (JavaScript on and off). Pixels decide visibility, not AA: the backstop asks whether the text is actually painted, uncovered and readable at all; AA (4.5:1, 3:1 for large text) stays with the CSS pass whenever the CSS pass resolves the colours, and with axe and the manual WCAG review. Targets are every rendered text node (display:contents wrappers included), every native control showing text (value, placeholder or chosen option) and every named element without painted text of its own (accessible names only, hit test only). Text is measured line by line: each text node's word ranges are grouped into line boxes, so one hidden line of a paragraph is found. The scan is directed at targets, not fixed bands: after a first look at the top of the page, every line not yet measured is scrolled into view (its scrollable ancestors, such as an app shell's main panel or a tab strip, first; then the document) and measured once finite animations have finished and the painted state of every element (opacity, transform, filter, clip-path, colours, position) is unchanged about 100 ms apart, so CSS and script-driven entrances and scroll reveals are measured at rest (bounded at 2 s per step; elements under infinite animations are left out). The page bottom is then collected again, and so is the end of every inner scrollport (an app shell's panel), so content added while scrolling is found, for at most four passes; a scan that stops at its step bound (300) or still finds new content after the last pass is INCOMPLETE. (a) A hit test at three points per line checks that the text, its own subtree or an ancestor is on top. An opaque cover (a replaced element other than an SVG, or a background colour at 90% or more opacity) at more than half the points obscures the line; a translucent cover (an SVG, which is mostly transparent shapes, a lighter background colour, a background image or gradient, a backdrop filter, other text) is compositing the CSS pass cannot see, so that line is graded by its pixels. Layers a hit test cannot see are possible covers too: a positioned `::before` or `::after` that paints, on the text's element or an ancestor (a loading veil, a scrim), and a positioned `pointer-events:none` layer that paints; a line under one at more than half the points is graded by its pixels at 3:1. Layers behind the text (negative z-index) are not covers. A gradient pseudo-element on an ancestor that clips its content is the fade of a truncated block (a "read more" clamp): the lines under it are cut text, not displayed, like a clipped line. On a declared state other than `default`, the top layer is respected: with a modal dialog open (or a shown element with `aria-modal="true"`) the rest of the page is inert and is counted as not displayed, page text an open popover covers is not graded, and the dialog's and the popover's own text are graded; a non-modal open dialog is not inert, so text it covers stays graded and is obscured. (b) Pixels: from a viewport screenshot after the page settles, over the middle 60% of the line box, the background is the modal colour, ink pixels differ from it by more than 24 in a channel, the readability ratio is the 90th percentile of the ink pixels' contrast against the background and the peak is the strongest ink pixel. Where the CSS pass resolved the colours and no translucent layer covers the line, the line fails only when it is effectively not painted: fewer than three ink pixels or a peak under 1.5:1 (colours that resolve to at least 3:1 but paint under 1.5:1 are hidden by an effect the CSS pass cannot see; light and thin weights that pass AA by colour are left to the CSS pass). Where the CSS pass could not resolve the colours, the pixels grade readability: under 3:1 is unreadable (under 1.5:1 for a line with fewer than 30 ink pixels, such as a single thin glyph). Rendered text under 4 px high is unreadable. Text that is obscured or unreadable with JavaScript on fails; text that is readable with JavaScript on but obscured, unreadable, unmeasurable or hidden with it off is an integrity mismatch, and a reviewed `jsOffDifferences` entry for it never makes it PASS. Text clipped to nothing by an ancestor that cannot be scrolled (an inactive carousel slide, an accordion collapsed with max-height:0), the same in both renderings, is not displayed: it is counted (`textHidden`) like display:none and graded through the declared states that show it. The width screen uses the same rule: content a collapsed box hides, and content wholly beyond the inline-end or block-end edge of a box that cannot scroll (the next slides), is not a clip, while content pushed wholly past the start edge and displayed content cut partly still fail. Text the backstop cannot measure (no box, outside the document, too few pixels, not reachable by scrolling, not reached before the bound) is INCOMPLETE, never PASS. Hide inactive content with `hidden`, `display:none` or `visibility:hidden`; visually hidden assistive text (the same sr-only rule as the width screen), an off-screen skip link that appears on focus, and the text of a disabled control (no contrast requirement in WCAG 1.4.3) are counted, not graded. Native authored strings (button-type input values, placeholders, option labels and accessible names) are copy: they are matched to the copy deck and screened for placeholders and filler like visible text, and a control's displayed value and its accessible name are compared separately with JavaScript off. The copy deck approves the displayed text and the accessible name separately (a slot's optional `ariaLabel`); a name identical to the displayed value is one string. A name taken by `aria-labelledby` from a hidden or undisplayed element is a name to approve the same way, and an approved `ariaLabel` must appear in its cited source like the text.

Automated contrast incomplete results: axe reports `color-contrast` as incomplete when it cannot resolve the colours (text over a photo, a gradient or a scrim). Such a result is resolved only when the backstop measured that exact element (the same composed path), with every line uncovered, at or above the AA ratio for its size (4.5:1, or 3:1 for large text) in BOTH renderings, and a PASS `wcag-review` record for the same screen, language and state cites the screenshot (its artifact is that state's approved frame or the checker's screenshot, or its note names one of them). The resolution is recorded per element (`contrastNodes`); any other incomplete rule, and any element that fails one condition, stays blocking. One exception covers the JavaScript-off rendering only: a declared non-default state reachable only by script, declared `requiresScript: true` with its trigger recorded, resolves on the scripted rendering alone (same element, AA and review conditions); the default state always needs both renderings, and a `requiresScript` claim on a state that renders with JavaScript off (every element the scripted rendering shows is shown without script) fails as an integrity mismatch.

ENH backlog: a future exception for an unresolved compositing effect is acceptable only with a pixel-measured proof per rendering (screenshot text-pixel contrast with the effect applied, a named approver and the evidence hash), never with token pairs.

At the 320 px reflow width, ordinary text or media overflowing any sideways scroller, to the left or the right, fails. A `table`, `pre`, `code`, `role="grid"`/`role="table"` with real rows, or an element marked `data-fannan-2d="reason"` is only a **candidate**, recorded in `evidence.json` with its element and reason and never excused automatically: its scroller must fit inside 320 px and be keyboard-usable, the text around it must reflow, resizable media is not a candidate, and every candidate needs a `reflowExceptions` decision in the handoff, or the final handoff is blocked. There is no cap on the number of candidates.

The accent must be the approved palette token (`colors.accent`, else `colors.primary`, from the hash-checked tokens). At final handoff an invalid or missing accent variable, or one that differs from the approved token, fails with a message naming the variable; the wireframe phase records the accent as DEFERRED, never PASS. The accent area is a DOM background-area proxy and is approximate; the screenshot review decides. The automated check does not measure accent area or coverage exactly and does not fail other off-palette colours painted on the page: accent area, coverage and stray colours are decided by the screenshots and the manual `accent-area` and `palette` reviews (panel A; R12 M19 closed on that basis). The accent does not have to appear on a control.

The spacing-scale probe checks all four margins (logical margins included; `auto` and 0 are ignored), padding and gaps. An element marked `data-fannan-spacing-exception="reason"` is recorded with its element, id, reason, values and screen/state/lang in the handoff evidence (`checks.spacingExceptions`). At final handoff it excuses its values only when the handoff has a matching `spacingExceptions` entry for that element id and screen/state/lang, with a reason and the approver as reviewer; otherwise the handoff is blocked (wireframes record it as DEFERRED). A blank reason, or an element without an id, excuses nothing. Margins on `html` and `body` are screened too.

Negative spacing **tokens** are banned: the approved scale holds only positive lengths, so a negative value is always off-scale. An approved margin exception (above, with the approver named) may still excuse a negative margin on one element; that is a reviewed per-element decision, not a token (R13 D1 closed on this basis).

Frames are never excused: there is no `frameExceptions` entry. axe and the design probes run in the main document only, so any `iframe`, `frame`, `object`, `embed` or `fencedframe` fails the final handoff (DEFERRED in wireframes). Where the design needs embedded third-party content (a map, a video, a booking widget), the handoff uses a **static poster** image in its place plus an **engineering note** in `HANDOFF.md` naming the embed, its source and where the engineer inserts it. In-frame scanning is revisited only once every gate runs inside frames (R13 q1).

## Pass/fail checklist

Every row is BLOCK unless explicitly marked WARN. `wireframe` evaluates the structure/copy column; visual-only criteria are recorded as deferred, never called PASS. `handoff` requires both columns and all fourteen manual IDs listed below.

| Rule | Pass mark | Evidence and detector | Phase |
|---|---|---|---|
| Point of view | One coherent idea tied to an audience, job and goal; all three cited | `point-of-view`: brief lines, rationale and annotated recommended direction | Both |
| Section and decision trace | 100% of sections, layout breaks, token choices and expressive media name the brief line and visitor job served | `brief-trace`: section/decision ledger matched to DOM IDs and screenshot | Both; token trace after styling |
| Centering | At most one centered principal section per page | DOM computed text alignment plus composition screenshot; reviewer catches nested/unmarked groups | Both |
| Accent area | At most 10% full-page and at most 10% reviewed viewport | Declared accent token(s), computed-style proxy, screenshot measurement including accent inside media/effects | Visual |
| Type sizes | At most six distinct rendered sizes per page/locale, all mapped to named type tokens | Token list and DOM computed `font-size`; inspect pseudo-elements/SVG/canvas text manually | Visual; structural hierarchy in grayscale |
| Centered icon trio | Zero rows of three centered icon-first feature blocks | DOM grouping and screenshot; changing tags or using SVG does not exempt it | Both |
| Generic hero | Zero vague transferable headlines, including a vague headline above three icon cards | `generic-hero`: writer/critic swap test and actual hero screenshot; a headline still valid for unrelated firms fails | Both |
| Default effects | Zero generic gradient heroes and zero stock glassmorphism | Background-image/backdrop-filter detector (computed on `html`, `body`, visible elements and rendered `::before`/`::after`, inside open shadow roots, plus constructed stylesheets and the raw text of every served CSS/HTML/SVG/JS file, style attributes and `<style>` elements, so the `-webkit-` alias and root-element filters that Chrome drops still fail; `data:`/`blob:` stylesheets are refused and unreadable unserved ones fail; same-origin frames are only partially inspected, for glass and width, and every `iframe`, `frame`, `object`, `embed` or `fencedframe` fails the final handoff) plus screenshot; decorative effects cannot be relabelled data visuals | Both in grayscale; visual final |
| Rounded-card grid | Zero repeated default rounded-card grids | `card-grid`: actual grouped content, borders/radii and screenshot; use the content's appropriate structure | Both |
| Purple-blue default | Zero default purple-blue decorative pairing | Color-role inventory and screenshot; semantic status color is reviewed for its job, never used as a second decorative accent | Visual |
| Decoration | Every non-content mark has a named comprehension, navigation, hierarchy or identity job | `decoration-job`: asset/element ID → brief line → purpose; unsupported marks are removed | Both |
| Dashboard tropes | Zero undifferentiated KPI-card rows, icon soup, color-only status, fake live tickers | `dashboard-tropes`: task-flow review, screenshots, data/source/timestamp labels and state checks | Both |
| Copy provenance | Every slot's displayed text appears in the brief or writer's deck; every claim maps to a checked, confirmed fact | Slot source lines + source revision/hash; writer checks names/location/partners against project rules | Both |
| Copy filler | Zero occurrences of `unlock`, `seamless`, `empower`, `cutting-edge` and their listed variants in visible copy | English word-boundary and normalized Arabic cliché scan; critic read-through in every required language | Both |
| Rule-of-three tagline | Zero empty three-part slogans | Headline-only automated punctuation/conjunction screening plus mandatory `rule-of-three` semantic review; useful three-item task/data lists are not slogans | Both |
| Stats/quotes/logos | Zero unconfirmed or unlicensed proof claims | Fact ledger, exact quotation/source, permission and asset manifest; numeric regex is only a warning detector for this broader review | Both |
| Placeholders | All visible as `[placeholder]` with IDs during draft; zero at final handoff | Copy deck + rendered DOM + placeholder inventory; scan lorem ipsum, TBD and hidden substitutes | Draft recorded; final BLOCK |
| Craft | Consistent named type/spacing/grid/color roles and purposeful hierarchy | `craft`: token sheet, alignment overlay, actual content and comparative reference critique | Structural before style; complete at handoff |
| Real reference comparison | Three inspected references with dated notes and project-specific lessons | `reference-work`: source URLs, captures/notes, what to adopt and reject, brief trace | Both |
| Complete accessibility evidence | No failed applicable WCAG 2.2 A/AA criterion or unresolved automated incomplete result (a colour-contrast incomplete result resolves only as set out under Automated contrast incomplete results) | `wcag-review`: axe (tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22a`, `wcag22aa` from `tools/axe-tags.mjs`, plus `target-size`; axe's experimental A/AA rules stay off and are manual) + keyboard/screen-reader/manual checklist + reference-state captures | Both at design level; full proof at handoff |
| All states/locales and copy fit | Every requested variant accounted for; no clipping, truncation or meaningless N/A | Component matrix, real translations, 150% synthetic stress evidence, LTR/RTL review | Both at current fidelity |
| Observational improvement | Optional non-blocking preference with owner and disposition | WARN only when no contract, accessibility, truth, approval or implementation question is affected | Both |

Six sizes serve six semantic tiers without making every label another style. Ten percent makes “about ten percent” a reproducible upper bound. The rules are intentionally strict constraints requested for this bot; they do not establish universal rules of good design.

## Manual evidence that the checker requires

`manualChecks` includes `point-of-view`, `brief-trace`, `generic-hero`, `decoration-job`, `card-grid`, `dashboard-tropes`, `rule-of-three`, `reference-work`, `craft`, `wcag-review`, `accent-area`, `palette`, `rules-copy`, `language-overflow`, `discovery-evidence` (the Step 1 discovery ledger), `navigation-findability` (Step 3 navigation model and its Step 5 findability test), `interaction-states` (reachable states beyond the seven), `form-behavior` (forms and consequential actions, or a justified N/A in the note), `task-test` (Step 5 neutral task testing and retests), `feedback-log` (the approver's feedback log), `emphasis-order` (the emphasis order and blurred-screenshot check), `type-measure` (the type scale with measure, line height and the SC 1.4.12 text-spacing check), `colour-roles` (the colour roles and token-level contrast matrix) `grid-per-width` (the grid for every declared desktop width) and `component-consistency` (each reused component matches its one shared definition on every screen; judged structurally in wireframes and fully at handoff). The `craft` artifact may hold the last four; each still needs its own record. In the wireframe phase `accent-area` and `palette` are DEFERRED, and `emphasis-order`, `type-measure`, `colour-roles` and `grid-per-width` are PASS or DEFERRED; every other ID needs PASS in both phases.

The feedback-log artifact records each item's exact words, scope, version, interpretation, decision, resulting change and confirmation. A deferral needs the approver's recorded disposition. Missing or unresolved items fail. If no feedback was received, record that explicitly with reviewer and scope. Every record identifies its screen, language and state, PASS/FAIL, reviewer, artifact path, brief line references and a concrete note. An artifact may cover several states, but each record identifies the part supporting its exact scope. The artifact contains the actual rubric/check result, screenshot references and measured values where relevant. Missing coverage for a screen is a failure even if another screen passed. A grayscale artifact records visual tests as deferred while judging structural craft; it does not sign off final color or typography.

The critic asks: with the company name masked, does the headline still express a precise offering, audience task or independently sourced distinction from this brief? Record the compared alternative categories and the reason. If it could be pasted unchanged onto arbitrary company sites, fail and return the slot to the writer. Do not replace an approved headline without the existing approval process.

For functional dashboards, derive content from the user's decisions and workflows. Use a ranked queue, trend or table when that is what the task requires; do not add a summary-card row merely because dashboards often have one. Every number requires a real source, scope and update meaning. Static sample data must be explicitly labelled as a fixture and cannot enter a real handoff as production data. “Live” requires a real documented data path; animation is not evidence.

## Accessibility evidence, accurately scoped

Record each text foreground/background pair and state. Normal text needs 4.5:1 contrast; large text needs 3:1 using WCAG's definition of large text. Contrast uses specified/computed colors, not antialiased screenshot edges. Do not round a failing ratio upward. [W3C contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

Applicable control boundaries, meaningful icons and graphical objects need 3:1 against adjacent colors. Record their actual role and applicable exceptions rather than claiming every decorative border must pass. Status also has a readable label or shape. [W3C non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

Record sequential keyboard focus, visible focus before/after, modal entry/escape/return, traps and sticky overlays. AA focus-not-obscured requires that the focused control is not entirely hidden by author content; prefer full visibility as this project's stricter usability target. Focus Appearance 2.4.13 is AAA, so do not mislabel it as the AA criterion. [W3C focus-not-obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum).

Measure actual pointer targets. A 24 × 24 CSS-pixel target is the baseline; any smaller target needs a documented qualifying spacing, equivalent-control, inline, user-agent or essential exception. Bounding boxes and an “inline” tag are only screening heuristics. [W3C target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum).

Test non-dragging alternatives for dragging operations, and accessible authentication without an unsupported cognitive test where authentication exists. If absent, record N/A with the screen inventory that proves absence. [W3C WCAG 2.2 additions](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/).

Check 200% text resizing and 400% desktop zoom/reflow (equivalent 320 CSS-pixel width), including applicable two-dimensional content exceptions. This is accessibility validation, not authorization to design phone layouts. Document browser zoom and viewport used. [W3C reflow guidance](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html).

Set the page language, mark language changes and specify base direction separately. Test real RTL content, mixed-direction identifiers, punctuation and numbers; use appropriate directional markup rather than reversing strings. [W3C internationalization guidance](https://www.w3.org/International/questions/qa-html-dir).

## Command and release decision

```sh
FANNAN_DEPS=/opt/fannan/deps \
node "$FANNAN_RELEASE/tools/pre-handoff-check.mjs" \
  /workspace/design-output/PROJECT/DESIGN.md \
  /workspace/design-output/PROJECT/reference.html \
  /workspace/design-output/PROJECT/evidence-vNN \
  PROJECT /workspace/design-output/PROJECT/handoff.json --phase=handoff
```

Use `--phase=wireframe` for the complete wireframe quality gate, run within the existing Step 5 gate after the task and navigation-findability tests and necessary retests; it must PASS before structure approval and Step 6. Replace `PROJECT` with the validated project slug and use a fresh output directory. A nonzero result blocks. A missing protected checker binary, dependency, reference, approval or manual evidence remains a failure; never replace it with a stub in a production run. The separate test suite may stub a boundary only when its output is clearly labelled test-only and cannot masquerade as release evidence.
