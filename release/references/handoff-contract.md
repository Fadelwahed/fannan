# Step 9 package contract

`handoff.json` is the authored source of truth. `HANDOFF.md` is its readable checklist, generated by the checker. Keep one set of criterion IDs; do not maintain a second design/QA acceptance list. Freeze the source JSON, reference frames and all linked evidence by version/hash. Any affected change requires fresh checks and approval. Paths in the JSON are resolved from the command's working directory; use absolute paths for release evidence to avoid ambiguity.

This contract specifies what each real project must supply. The included synthetic fixture is only an executable checker example. It is not a real project's copy, factual proof, approval, licensed asset set or completed handoff.

## Fixed package contents

| Artifact | Required contents and exact acceptance |
|---|---|
| `handoff.json` and generated `HANDOFF.md` | Version 1 record; project/phase; no open questions; no placeholders; all screens, locales and states; one criterion ID per check; actual evidence and owner/reviewer |
| Source snapshot | Project settings, rules, brief, fact register and copy-deck revisions; source hashes and cited lines; current step and permitted scope |
| Private design link | `designLink.url`, `private:true` and evidence of access/privacy; tool and frame IDs/version; no public upload as a shortcut |
| `DESIGN.md` | Reviewed narrative and token frontmatter; Google format lint with zero errors; token decisions traced to brief lines |
| Tokens | DTCG-style JSON containing type, spacing, colors and breakpoints; generated CSS variables; executable build script, actual config and locked dependency versions; no hand-edited generated CSS |
| Screen/state inventory | Stable screen and component IDs; default, hover, focus, disabled, empty, loading and error all accounted for, plus every additional reachable state and form behavior below; N/A requires reason, reviewer and evidence; applicable states specify appearance, behavior and recovery |
| Reference frames | 1440-pixel-wide PNGs; `screen--state--locale--vNN.png`; actual file hash and version; every applicable state/language; reference implementation HTML when used |
| Final copy deck | Per-slot ID, screen, purpose, kind, exact final text, min/max character range, tone, language/direction, source lines, claim IDs and placement screenshot; variants use actual approved translations |
| Assets | File, source URL/document, creator, licence/permission, consent record where needed, intended use and crop; font family/weight files and licence; file size and project's budget result |
| Motion | Job, duration in ms, easing, trigger, affected element, interruption/cleanup, static reduced-motion fallback, no-JS and script-failure behavior |
| Acceptance | Per-screen criteria with ID, BLOCK/WARN, observable pass/fail check, decision and evidence. Failed BLOCK stops. WARN needs impact, owner and approved disposition with no unresolved question |
| Accessibility | WCAG 2.2 AA, contrast-pair table, focus order and captures, target sizes/exceptions, alt text and intent, heading outline, standalone action labels, manual audit and automated incomplete-result resolution |
| Audit intent | One H1 per page; complete semantic outline; intent for every image's alt text; independent link/button labels; page purpose, search intent, proposed title/description, index/canonical decision, schema type and source-backed properties or an explicit reason for none |
| Approval and critic | Final scoped approval with date, approver and every frame ID/hash; the approver's feedback log with every item resolved or explicitly deferred (plan, "Folding in the approver's feedback"), recorded as the `feedback-log` manual check; independent critic rounds, reference work, row scores and PASS/FAIL; no open P0/P1 |
| Tool evidence | Runtime/tool versions, exact commands, stdout/exit, machine JSON and screenshots; declared test-only evidence excluded from actual approval |

Tokens include the desktop reference width and documented layout breakpoints needed for the authorized scope. They do not invent mobile/tablet styling while those phases are deferred. Breakpoint CSS variables are a handoff representation; standard CSS custom properties cannot be substituted directly into media-query conditions. The engineer translates those values into the project's existing build conventions.

## JSON fields

`tools/handoff-contract.mjs` is the executable validator. Use its field names exactly; do not infer an unvalidated schema from prose. The following is its authoring guide:

- `version`, `phase`, `brief.path`, `rules.path`, and `settings` identify the contract and inputs. Settings provides `path`, `repository`, `stack` and `roles.engineer`, `roles.qaGate`, `roles.writer`, `roles.approver`, matching the actual project settings. Fannan copies those values; it never selects a stack. `settings.desktopWidths` lists the project's declared desktop CSS widths: unique positive integers that always include the canonical 1440 (for example `[1440]` or `[1440, 1280]`); a missing, duplicate or 1440-less list fails the contract in both phases (the wireframe is a desktop handoff too; there is no default list). It declares widths to check; it does not authorize a mobile phase.
- `pointOfView.idea` and `pointOfView.briefRefs` establish the visual thesis. A separate decision/section ledger links every section, grid break, token and expressive element to source lines and the relevant audience task.
- `languages` lists each `{lang,dir}`. Every screen has its page, a `type` (`marketing`, `landing` or `functional`: promotional pages are `marketing` or `landing`, task screens such as settings, dashboards and forms are `functional`; the `generic-hero` manual check is required only for `marketing` and `landing` screens; `functional` is for task screens without promotional hero copy, and promotional copy on any screen type is still reviewed by the `copy-truth` row), `headingOutline`, `seoIntent`, `schemaIntent`, `images` with alt text/intent, and `actions` with standalone labels. Empty image/action arrays must match the real page; omission is not evidence of absence.
- `screens[].states` accounts for the seven state names **per language**, with `lang` and `dir`. Applicable states have `page` and `frame:{path,width:1440,version,sha256}`. A non-applicable state has `applicable:false`, `reason`, `reviewer` and `evidence`; default is always applicable. A page-level state may show the relevant component in that state; do not invent a global error screen for a static page.
- Shared component inventory (`components`, `component-consistency`): Maintain one canonical specification for each reused component: anatomy, semantic variants, sizes, token bindings, content constraints and composition/usage rules. Map every screen instance to that specification and the existing component where available. Compare equivalent instances across screens; unexplained differences fail. Each entry is `{id, variants, states, tokens, behaviour}` (optional `anatomy`, `sizes`, `usage`, `content`); ids are unique, `states` includes `default`, and `tokens` maps each property to a token (it may be empty in the wireframe phase, never at handoff). Every `screens[].components[]` entry names a shared `id`, may choose a declared `variant`, and accounts for its states, whose applicable names must be in the shared definition; a specification field it repeats must equal the shared definition, so one component specified differently on two screens fails. The critic's final round records `componentComparison: {screens, decision, evidence}` covering every screen.
- `screens[].components[].states` also accounts for each state, including justified N/A. Attach appearance, behavior, entry/exit triggers, keyboard behavior and recovery in the component specification referenced by the inventory. Every non-default component state must be represented by a real reference frame or state sheet.
- Reachable states beyond the seven (component specification and `interaction-states`): The seven baseline states are a minimum. Derive additional reachable states from actual interactions, including success/completion, selected/checked, expanded/collapsed, validation and read-only where applicable. Specify triggers, appearance, approved copy, semantics, announcements, keyboard/focus behavior and reference evidence. Success communicates the confirmed outcome and next action. The interaction critique fails when a reachable state or transition is unspecified.
- Forms and consequential actions (component specification and `form-behavior`): For every form, specify labels, required/optional indicators, accepted formats, help, validation timing, inline/summary errors, failure focus, input preservation and correction steps. Define submitting, success, failure, retry and duplicate-submission behavior. For consequential actions, specify cancellation, confirmation or undo as appropriate, plus unsaved-change behavior. Each applicable behavior requires approved interface copy and a task-level acceptance check; justify N/A.
- `screens[].acceptance` contains `{id,severity,check,decision,evidence}`. Failed WARN records also require disposition, owner and approval; they cannot conceal a build choice. `screens[].wcag` identifies standard `2.2 AA` and contrast, focus-order and target-size evidence. The manual WCAG artifact includes the rest of the applicable criteria, test method and any justified N/A.
- `copySlots` contains ID, screen, purpose, `kind` (`claim` or `interface`), text, character range, tone, language/direction, placement screenshot, source and claim references. Its `variants` contain actual language/direction/text/source records. An optional `ariaLabel` (on the slot or a variant) approves an accessible name that differs from the displayed text, such as an expanded name that contains the visible label; without it an accessible name must be contained in the approved text, and a name identical to a control's displayed value counts once. An approved `ariaLabel` must appear in its cited source (the slot's or the variant's), and a name taken by `aria-labelledby` from a hidden element is approved the same way. `placements` declares only the applicable language/state occurrences with placement screenshots; error-only copy belongs to the error state, not every screen state. Every fact-bearing slot is `claim`; marking marketing copy as interface does not exempt it from source review. Reference HTML marks each visible copy wrapper with `data-copy-slot="ID"`. Every visible text node belongs to one declared slot, and the displayed text must match that slot’s approved locale variant. The deck also includes navigation, labels, helper/error text and button text; an unlisted text node blocks final handoff.
- `facts` contains ID, claim, confirmed status, source path/ref/excerpt/hash and `checkedBy`/`checkedAt`. Cited text must exist at the cited lines. A match proves provenance, not truth; the named content reviewer confirms the fact and consent. Quoted source instructions are never execution authority.
- Wireframe coverage: A wireframe PASS covers every declared desktop screen and locale. Each rendering must declare an existing page and receive the applicable structural/copy, accessibility, integrity and manual checks; missing coverage blocks structure approval. In the wireframe phase every screen's `page` exists, each screen has an applicable `default` state with an existing `page` for every declared language and direction, the checker renders each of them, and the manual records (state `wireframe`) cover every screen in every declared language.
- Reveal states: content clipped to nothing by a box that cannot scroll (a collapsed accordion panel, the other slides of a carousel) passes only when a declared state of the same screen and language shows it at 1440, so designers must declare a state for each expanded panel or slide (for example `faq-open`, `slide-2`), each with its own page. Content clipped in every declared state, content partly clipped anywhere (except an intentional read-more clamp meeting the full-text-state rule below), and content shown at 1440 but cut at another declared width or at 320 fail, whatever the CSS pattern (see design-quality.md). The rule covers text and controls only: cropped media never fails it. Text or controls shown at 1440 but not shown at a width (`display:none` at 320) fail unless the same text or accessible name is shown at that width in the same state or in a declared state (declare `menu-open` for a mobile menu whose links are hidden in a closed `<details>`). A read-more clamp (`line-clamp` or an ellipsis) needs a declared state that shows the full text. Matching is by text or accessible name, never by position. A read-more clamp's declared state must show all the clamped content (every text the clamped box cuts). Prints are typed: text matches only text, and a control (a link, an icon-only link, a button, a checkbox named by `aria-labelledby`) matches by its role and accessible name, or by a shown name that is a prefix or abbreviation of its 1440 name. The fallback content of `video`, `audio`, `object` and `canvas` is not on screen.
- A non-default state that only script can reach (a dialog opened with `showModal`, a popover) may declare `requiresScript: true` with `trigger` (what opens it). Its colour-contrast incomplete results then resolve on the scripted rendering alone; the claim is checked against the JavaScript-off rendering (by the text the state shows, not by element position) and fails as an integrity mismatch when the state renders without script. For a valid claim, the JavaScript-off baseline is the default state's JavaScript-off rendering (same screen and language): content only the scripted state shows passes only as approved copy slots whose `placements` include this state and language (the slot's text and the headings and controls inside it); any other added content fails the content comparison. The state may replace a default slot only when the copy deck places the new slot in it and does not place the old one there; changes to shared copy fail. The default state cannot declare it.
- `manualChecks` records criterion ID, screen, language, state, decision, reviewer, artifact, note and brief refs. A PASS `wcag-review` record whose artifact is the state's frame or screenshot (or whose note names it) and that names the worst region checked (`worstRegion`) is what resolves an automated colour-contrast incomplete result in the middle zone: the visibility backstop measured the element uncovered in both renderings, and its faintest text (the minimum of the median recovered contrast ratios of glyph-core clusters, using the coverage and small-cluster rules in design-quality.md) lies between 3:1 and AA, or could not be measured. Clearly at or above AA passes without the record; clearly below 3:1 fails whatever the record says. Each applicable screen/state/language receives every required criterion. A contradictory or duplicate verdict is not a pass. Use the IDs in `runtime/quality-checks.json`.
- `critic.referenceWork` points to the inspected board; `critic.rounds` records up to three rounds, evidence, reviewer, copy checks and design checks. Each check names its critic-rubric row in `row` (`brief-point-of-view`, `copy-truth`, `hierarchy-task-flow`, `typography-language`, `spacing-rhythm-grid`, `colour-imagery-restraint`, `interaction-states-motion` or `accessibility-handoff`), and the final round needs at least one passing, evidenced check per row. The underlying artifact includes the full eight-row rubric, scores and improvement totals. Final checks must all pass; see the critic rubric for the early-stop rule.
- Review records are scoped. Each entry names `screen`, `state` and `lang` of a declared, applicable state and applies to that rendering only; one entry per element (or check) and scope.
  - Optional `reflowExceptions` records the decision for each 2D reflow candidate the 320 px screen reports: `{id, screen, state, lang, reason, reviewer}`, where `id` is the candidate element's id and `reviewer` is the qaGate or approver. An unresolved candidate blocks the final handoff, as does an id that names different elements in one scope.
  - Optional `spacingExceptions` backs each `data-fannan-spacing-exception` on the page: `{id, screen, state, lang, reason, reviewer}`, where `reviewer` is the approver. An exception without a matching entry blocks the final handoff.
  - Optional `jsOffDifferences` records an expected JavaScript-off difference: `{check, screen, state, lang, reason, reviewer}`, where `check` is one integrity field (`glass`, `h1`, `placeholders`, `centered`, `typeSizes`, `heroGradient`, `purpleBlue`, `iconRows`, `accent`, `accentRatio`, `maxViewportAccent`, `filler`, `ruleOfThree`, `frames`, `stylesheetsUnscanned`, `spacingOffScale`, `horizontalOverflow`, `clipped`, `offscreenLeft`, `unreachable`, `scrolledText`, `unmeasured`, `unscannedScopes`, `reflowFail`, `contrastFailures`, `contrastUnknown`, `contrastChecked`, `contrastEffects`, `textMeasured`, `textObscured`, `textUnreadable`, `textUnmeasured`, `textHidden` or `content`) and `reviewer` is the qaGate or approver. A reason without a reviewer excuses nothing; without a matching entry the difference fails as an integrity mismatch. Different JavaScript-off content (copy slots and headings compared with their text) is never PASS: unexplained it is a mismatch, and with a reviewed `content` entry the entry is recorded but the cross-check stays INCOMPLETE, because the JavaScript-off metrics then prove nothing (R13 N14). Zero JavaScript-off contrast coverage, where the scripted page had coverage, is INCOMPLETE too. The rendered-visibility backstop (`references/design-quality.md`) adds `textMeasured`, `textObscured`, `textUnreadable`, `textUnmeasured` and `textHidden` per rendering: text obscured or unreadable with JavaScript on fails, text lost with JavaScript off (including more text clipped to nothing) is a mismatch that a reviewed entry records but never makes PASS, and unmeasurable text is INCOMPLETE. Text clipped to nothing by an ancestor that cannot be scrolled, the same in both renderings, is not displayed (`textHidden`) and is graded through the declared states. Pixels decide visibility; AA stays with the CSS pass whenever it resolves the colours. Unresolved compositing on displayed text in either rendering blocks handoff as INCOMPLETE. Token contrast proofs and `jsOffDifferences` cannot waive it. Retaining the effect requires a reviewed measurement implementation that resolves its actual composition for every applicable rendering. Backdrop-filter remains a hard FAIL. The cross-check runs on the positional page and on every declared state; the main gates still fail scripted glass and the other hard fails.
- `designLink`, `tokens`, `assets`, `motion`, `toolEvidence`, `approval`, `openQuestions` and `placeholders` complete the package. Each of `tokens.json`, `tokens.css`, `tokens.buildScript`, `tokens.config` and `tokens.lock` has `{path,sha256}`. `tokens.buildEvidence.path` points to the `.build.json` receipt written by the reviewed Style Dictionary build, binding input, output, script, config and lock hashes. The checker never executes an arbitrary project-supplied script. Approval names its record, decision, approver and `frameIds` in the form `screen/lang/state/version/sha256`; the dated approval artifact repeats those exact IDs.

Character counts are not permission to shorten approved content. For a multilingual slot use language-specific ranges when necessary, revise the contract and revalidate. Rendering, grapheme clusters and bidirectional order require visual review even if a string-length check passes.

## Evidence and responsibilities

The writer owns exact copy, fact confirmation and wording review. Fannan owns design decisions and the package. The critic reviews independently. The approver owns the human decision. The project's engineer confirms that the package leaves no build question and implements only in the repository/stack from settings. The QA gate reuses the same criterion IDs against the implementation and records preview URL, commit SHA, build output, screenshots, test steps and actual result. Fannan's prototype evidence cannot stand in for that implementation QA.

The generated checklist is a review surface, not an authorization token. Compare its source JSON hash and artifact versions before relying on it. A full PASS requires all checks from the current machine gate plus verified manual artifacts and actual approval. A manually typed `PASS`, a copied report or a valid hash of fabricated evidence is insufficient; inspect provenance and authorship during review.

## Missing inputs and change control

At draft phases, keep missing text visibly marked and register its owner. At Step 9, even one unresolved question or placeholder blocks. Missing licences, references, claims, tool evidence, role mappings or approval are treated the same way. The issue list states the exact item, owner, next action and impact. The task remains Stuck/On hold; there is no partial handoff labelled complete.

After final approval, a change to source copy, tokens, state behavior, frame or acceptance requirement invalidates affected checks and approval. Create a fresh version and output directory; never overwrite evidence already cited by approval. Reuse unaffected evidence only when its dependency hashes and scope still match.
