---
name: design-prototype
description: Turn a brief-backed screen idea into a reviewed clickable design prototype within the project's current design stage.
---

Read `design-process`, the current brief step, project settings/rules, copy and UI map. Verify the pinned manifest at session start. Before each write run `"$FANNAN_RELEASE/tools/readonly-precheck.sh" "/workspace/design-output/<project>/" "<project>"`; use the reviewed safe-write path. Stop if either check fails. Work only in the project's design tool or standalone mocks under `/workspace/design-output/<project>/`; never edit code in the repo. Ask the owner before anything paid, every time. See [security and install](../../references/security-and-install.md).

1. **Plan:** state the goal, screens, current step, evidence, checks and any cost; obtain the project's approver's yes for the plan and record the task. Under the existing authority record this role resolves to the owner; a different or missing mapping blocks the gate.
2. **Shape:** map one click path and each section to a brief line. Use the writer's real copy before layout; show missing text as `[placeholder]` with owner.
3. **Explore:** make 3–5 named, private variants along a clear design dimension. The approver chooses one; only that variant proceeds.
4. **Implement:** use `design-canvas` and the configured tool; if it cannot prototype, produce a standalone HTML mock in the allowed output folder. Respect grayscale through Step 5, the widths the brief scopes and every text length/language/direction requirement. The prototype is reference only.
5. **See:** capture rendered 1440px frames, interaction states and accessibility evidence. Do not crop longer copy. At Step 4, check grayscale structure, copy and provenance and record issues for testing. Within the existing Step 5 gate, after the task and navigation-findability tests and necessary retests, run `FANNAN_DEPS=... node "$FANNAN_RELEASE/tools/pre-handoff-check.mjs" <DESIGN.md> <page.html> <evidence-dir> <project> <handoff.json> --phase=wireframe` for the full desktop set; require PASS before structure approval and Step 6. It runs inside that gate rather than creating a new one.
6. **Critic:** a separate read-only reviewer scores copy and design together using [critic rubric](../../references/critic-rubric.md) and real references. The critic also compares each reused component across all screens against its shared definition (component inventory); an unexplained difference fails. Fix and rescore at most three rounds. Stop if a round gains <1 total point. A cap or stalled score is never a soft pass; send the scores and open defects to the approver. Any P0/P1 blocks handoff.
7. **Harden:** before Step 9 run `FANNAN_DEPS=... node "$FANNAN_RELEASE/tools/pre-handoff-check.mjs" <DESIGN.md> <page.html> <evidence-dir> <project> <handoff.json> --phase=handoff`. Require PASS evidence and complete [handoff contract](../../references/handoff-contract.md). Every non-default state that rescues hidden content declares its `opener` and `reveals` selectors, for example `{"state":"menu-open","lang":"en","dir":"ltr","page":"menu-open.html","opener":"details.mnav > summary","reveals":"details.mnav .panel"}`. Carousel slide states use the same fields plus an explicit `carousel: { "root": "#gallery", "slides": ["#slide-1", "#slide-2"] }` mapping; declare a state for every registered slide including the first (complete inventory), e.g. `{"state":"slide-2","lang":"en","dir":"ltr","page":"slide-2.html","opener":"#next","reveals":"#slide-2","carousel":{"root":"#gallery","slides":["#slide-1","#slide-2"]}}`. A verified carousel step is proven by the target slide being hidden in the source and fully shown in the declared state (no extra positive open attribute required); `aria-expanded=false` remains an explicit veto. The carousel opener must be a real button (`<button>`, `input[type=button]`, `role=button`) or a slide-picker `role=tab`, never a link or plain element, and must still exist in the declared state; every `reveals` match must lie inside a registered slide; at least two registered slides must actually be observable across the declared states (a never-shown sibling does not count). Undeclared horizontal clips fail closed. The gate verifies the region is hidden and the opener operable in the losing state, and for ordinary disclosures the opener open and the region shown in the declared state; an invalid declaration rescues nothing. WCAG 2.2 AA is the minimum.
8. **Review/share:** collect versioned private link, screens/states, evidence, critic history and walkthrough; use `design-share`. No public sharing without the owner's yes.

## Gotchas

- A plan approval, variant pick and final design approval are separate records. Do not infer one from another.
- Missing copy/facts, manual accessibility checks or open questions block Step 9 even if automated checks pass.
