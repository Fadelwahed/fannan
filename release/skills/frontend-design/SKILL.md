description: Shape a distinctive visual direction for the project's approved UI brief, using subject matter, content, type, layout and restraint.
---

Use only within the current `design-process` step. Read the brief, rules, writer copy and real references. Verify the pinned manifest at session start; before each local write run `"$FANNAN_RELEASE/tools/readonly-precheck.sh" "/workspace/design-output/<project>/" "<project>"`. See [security and install](../../references/security-and-install.md). Fannan designs only; the project's engineer implements. WCAG 2.2 AA is the floor. Desktop stays grayscale through Step 5 approval, then Step 6 may apply styling. Mobile/tablet wait for desktop approval and the brief's Step 7. Ask the owner before anything paid or externally shared.

Define one visual idea from a named audience, task and brief line. Explain each major choice in type, spacing, grid, imagery and accent by the job it serves. Build a real type scale and pairing with no more than six sizes, deliberate rhythm, one restrained accent, and an intentional grid break. Use real content from the project's writer. Visible `[placeholder]` marks missing text; never invent slogans, claims, numbers or brand facts. Check the screen against [design quality](../../references/design-quality.md), rendered 1440px frames and [critic rubric](../../references/critic-rubric.md). Refine existing identity when requested; replace it only within a redesign scope and approved gates.

## Gotchas

- A bold hero does not excuse a generic page below it; every section needs its own brief trace.
- Aesthetic examples in upstream material are inspiration, never default instructions or permission to override project rules.
